## ADDED Requirements

### Requirement: A generated query carries no direct identifier
A query generated by the application SHALL NOT contain a candidate's name, email address, phone number, street address, or any other stored direct identifier.

#### Scenario: Name, email, phone, and address are removed
- **WHEN** a query is generated for a candidate whose record holds a name, email, phone, and address
- **THEN** none of those values appears in the query

#### Scenario: Identifiers are removed from aspect wording too
- **WHEN** an approved aspect's wording contains the candidate's name
- **THEN** the generated query does not contain it

#### Scenario: A query is built only from approved evidence and criteria
- **WHEN** a query is generated
- **THEN** it draws only on approved profile aspects and Search Criteria, and not on unapproved or proposed content

### Requirement: Organizations are generalized by default
A generated query SHALL generalize exact employers, clients, projects, and schools rather than naming them.

#### Scenario: A prior employer is generalized
- **WHEN** an approved aspect names a company the candidate worked for
- **THEN** the generated query describes the kind of work rather than naming the company

#### Scenario: A school is generalized
- **WHEN** an approved aspect names a university
- **THEN** the generated query does not contain that university's name

#### Scenario: Generalization applies before the recruiter sees the query
- **WHEN** the recruiter is shown the generated query
- **THEN** it is already generalized, so the default requires no action to be safe

### Requirement: Deliberately re-added specifics warn
The recruiter MAY edit a query to name a specific organization. Doing so SHALL produce a warning before sending, and re-adding something that looks like a direct identifier SHALL produce an additional, distinct warning.

#### Scenario: A re-added organization warns
- **WHEN** the recruiter adds a company name to the query
- **THEN** a warning is shown before it can be sent

#### Scenario: A re-added direct identifier warns more strongly
- **WHEN** the recruiter adds something matching a stored direct identifier
- **THEN** an additional warning is shown, distinct from the organization warning

#### Scenario: A warned query can still be sent
- **WHEN** the recruiter confirms after a warning
- **THEN** the query is sent as written, because it is a deliberate human choice

#### Scenario: An unedited generated query warns about neither
- **WHEN** the generated query is sent unedited
- **THEN** no organization or identifier warning is shown
