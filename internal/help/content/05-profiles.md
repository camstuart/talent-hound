## Aspects

A profile is a list of aspects. Each aspect has a type — skill, experience, qualification, seniority, location, work arrangement, work rights, employment type, compensation, responsibility — a wording, sometimes a normalised value, and at least one citation.

The normalised value is what makes comparison possible: "Melbourne" as a city, "permanent" as an employment type, "AUD 180,000" as a currency, an amount, and a basis. It is only ever recorded when the source states it.

## Candidate profiles need approval

A candidate profile starts proposed. Nothing uses it — no search, no shortlist, no draft — until you approve it. You can edit any wording, remove an aspect, or add one of your own.

An aspect you wrote is marked as yours and is never silently overwritten. Re-extracting produces a proposed set of changes — additions, removals, conflicts — for you to accept or reject.

## Role profiles are automatic

A role profile is built from its listing without asking you, because nobody is being described. You can still edit it, and a hand-entered requirement behaves exactly like an extracted one except that it cites your record rather than a document.

## Staleness

A profile is stale when its sources have changed since it was built. Staleness is worked out by comparing what the profile was built from with what is there now — it is not a flag someone remembers to set, so it cannot be wrong.

A stale profile still works. It is labelled, and you decide whether to rebuild.
